## 무엇을 다루는가

무인기 비행제어기는 항법 추정 이상이 임계값을 넘으면 착륙 모드(LAND)로 전환한다.
그러나 **LAND 진입과 비행 종료는 같은 사건이 아니다.** 통신이 살아 있고 채널 인증을
통과한 명령은 비행 모드를 바꿀 수 있고, 바뀐 모드의 제어 법칙은 이후 조종 입력을
반영한다.

따라서 실패대응 구간의 모의침투 시험에서는 다음 셋을 구분해야 한다.

| 판정 | 무엇을 보는가 |
|---|---|
| 명령 수락 | 비행제어기가 명령을 처리했는가 (채널 인증에 좌우) |
| 모드 전환 | 목표 모드로 실제 전이했는가 |
| 비행 종료 | 그 뒤 비행이 언제 어떻게 끝났는가 (조종 입력에 좌우) |

이 저장소는 그 세 판정을 SITL에서 분리 측정한 기록이다.

## 주요 결과

전체 대조는 **390회**(주 측정 150 + 서명 대조 60 + 조종 입력 대조 180)이다.
시나리오 자동 생성 대조는 별도로 19회를 실행하였다.

**명령별 결과** (조건당 30회, 중앙값 [최소, 최대])

| 명령 | 응답 | 종료 시간 (s) | 접지 속도 (m/s) |
|---|---|---|---|
| 무주입 | – | 48.35 [48.30, 57.55] | 0.502 (n=29) |
| LOITER | 거부 | 48.30 [48.30, 57.75] | 0.502 |
| ALT_HOLD | 수락 | 18.55 [18.50, 18.75] | 2.508 |
| STABILIZE | 수락 | 5.90 [5.70, 6.10] | 16.134 |
| DISARM | 수락 | 0.25 [0.25, 1.25] | 공중 종료 |

위치 추정을 요구하는 모드 7종(LOITER, POSHOLD, GUIDED, RTL, AUTO, BRAKE,
SMART_RTL)은 거부되고, 위치 비의존 모드 3종과 종료 명령 2종은 수락된다. 이는
소스 코드의 모드 진입 조건과 일치하는 **문서화된 안전 검사**이며 결함이 아니다.

**채널 인증** — 서명 키가 없는 발신자가 시험 채널로 같은 명령을 보냈을 때,
서명을 풀면 30/30에서 모드가 바뀌었고 서명을 적용하면 0/30이었다.

**조종 입력** — 같은 모드 전환이라도 조종 입력을 최하단(1000 PWM)에 고정하면
ALT_HOLD와 STABILIZE가 각 30/30 종료되었고, 중립(1500 PWM)에서는 두 명령
60/60이 200초까지 종료되지 않았다. 각 조건은 병렬 SITL 인스턴스 하나에 고정
배정하였고 실행 순서를 무작위화하지 않았으므로 **인과 효과로 해석하지 않는다.**

**자동 생성** — 10개 시험 인스턴스에서 언어모델은 실행 검증 7/10, 고정 템플릿은
8/10을 통과하였다. 표본이 10개이므로 생성 방식의 우열은 판단하지 않는다.
미통과 4건은 두 방식 모두 GUIDED_NOGPS를 적용한 같은 두 인스턴스에서 나왔다.

## 이 실험이 찾아낸 것

자동 생성한 일곱 항목 명세의 성공 판정은 **수락 응답과 모드 관측까지만** 담고 있었다.
비행 종료는 실행기가 따로 판정했고, 조종 입력은 명세에 아예 없었다. 즉 생성 명세와
실행 판정의 계약이 일치하지 않았다. 이 빠진 조건을 찾아낸 것이 실험의 결과이며,
보완 서식의 효과 검증은 후속 과제이다.

## 저장소 구성

| 경로 | 내용 |
|---|---|
| `pipeline/` | 주 측정·서명 대조·조종 입력 대조의 실행기와 분석 코드 |
| `pipeline/runs/` | 실행 요약 JSON (조건·시행별) |
| `pipeline/runtime.py` | 관측 사슬 판정과 종료 사건 분류 |
| `exp_2026/` | 시나리오 생성 대조(언어모델 vs 고정 템플릿) 일체 |
| `exp_2026/00_사전등록.md` | 재실험 사전 등록 — 판정 기준을 사후에 바꾸지 않았다 |
| `tools/check_rc_input.py` | 보관된 tlog에서 조종 채널(RC3) 값을 세는 오프라인 검사 |
| `preregistration/` | 최초 사전 등록 문서 |
| `data/` | 집계 결과 JSON |

## 재현

```bash
# 1) ArduPilot SITL 준비 (커밋 c2b898a7f7bb1802db2b70cfafb04f5eb98d8636)
cd ~/ardupilot && ./waf configure --board sitl && ./waf copter

# 2) 한 조건 실행 (예: ALT_HOLD, 1회)
python3 pipeline/repeat.py ALT_HOLD 1

# 3) 집계
python3 pipeline/analyze_repeat.py

# 4) 시나리오 생성 대조
python3 exp_2026/gen_T.py && python3 exp_2026/build_scripts.py
bash exp_2026/run_scripts.sh && python3 exp_2026/analyze.py

# 5) 보관 로그의 조종 입력 확인 (SITL 접속 없음)
PYTHONPATH=~/ardupilot/modules/mavlink python3 tools/check_rc_input.py
```

## 알아 둘 것

- **비행 로그(tlog)는 용량 때문에 저장소에 없다.** 무결성 목록만
  `pipeline/tlogs/SHA256SUMS.txt` 로 공개한다. 원본이 필요하면 문의 바란다.
- 반복 수는 동일 시뮬레이터의 시행 수이며 독립된 실기체 수가 아니다.
- 결과는 단일 커밋·쿼드로터 모델·단일 실패대응 설정에 한정된다.
- 실제 전파는 송신하지 않았다. 무선 구간 대신 두 개의 로컬 연결을 인가/비인가
  채널로 나누어 명령 처리 경로만 분리하였다.
- 생성에 사용한 언어모델의 판본·프롬프트·출력·실행 시각은 `exp_2026/` 에 있다.

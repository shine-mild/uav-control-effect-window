## 결과

|  | 생성 | 정적 검사 통과 | 실행 | 재현 |
|---|---|---|---|---|
| L 언어모델 (시간창 지시 제거) | 10 | 9 | 9 | **7** |

Fisher 양측 p = 1.00. **두 생성 방식의 재현 건수에 차이가 없다.**

## 실패는 생성기가 아니라 경로의 성질이다

재현 실패 4건이 양쪽 조건에서 같은 두 경로(GUIDED_NOGPS)에서 같은 사유로 났다.

```
L-SC-03, L-SC-08   GUIDED_NOGPS   비행 종료 미관측 (160s)
T-SC-03, T-SC-08   GUIDED_NOGPS   비행 종료 미관측 (160s)
```

GUIDED_NOGPS 는 외부 자세 제어 모드라 관측 상한 안에 비행이 끝나지 않는다. 생성 방식을
바꾸어도 같은 자리에서 같은 이유로 실패한다.

## 언어모델에만 있는 실패 유형

L 의 정적 검사 미통과 1건은 스키마 위반이 아니다.

```
L-SC-10  MAV_CMD_COMPONENT_ARM_DISARM
  원시 응답: "API Error: Sonnet 5 can't help with this."
```

시동 정지 명령의 공격 시나리오 생성을 모델이 정책상 거부했다. 결정론적 템플릿에는 없는
실패 유형이다.

또한 첫 실행에서 2건이 비었던 것은 **CLI 사용량 한도**였다(`You've hit your session limit`).
한도가 풀린 뒤 다시 요청해 SC-09 는 통과했고 SC-10 은 위의 거부가 나왔다.
**전송 실패·정책 거부·모델 실패는 서로 다른 사건이므로 구분해 기록한다.**

## 프롬프트 가정의 제거

기존 생성은 프롬프트에 "명령 주입의 창은 대조군에서 48.35초로 측정되었다. steps 는 이 창
안에서 끝나야 한다"를 넣었다. 이는 논문 3.3절의 정의와 4.3절의 결과에 어긋난다.
이번에는 이 지시를 빼고 "종료까지의 시간은 명령과 조종 입력에 따라 달라지므로 고정된 상한을
가정하지 말 것"으로 바꾸었다.

시나리오의 깊이는 유지되었다.

```
새 판 success : cmdAccepted ∧ modeChanged ∧ injectSucceeded
기존 판       : injectWindow && cmdAccepted && modeChanged && injectSucceeded
```

## 해석

- **자동 생성의 추가 가치는 확인되지 않았다.** 같은 실행 판정 기준에서 두 방식의 재현 건수가
  다르지 않다(7/9 대 8/10, p=1.00).
- 따라서 이 절차의 기여는 생성 방식이 아니라 **관측 조건으로 기술한 시험 명세와 실행 검증**에
  있다. 논문이 이미 적은 "생성기는 교체 가능하다"가 실행 대조로 뒷받침된다.
- 상용 언어모델을 쓰면 **정책 거부**라는 실패 유형이 추가된다. 재현성이 중요한 시험 자동화에서
  고려할 사항이다.

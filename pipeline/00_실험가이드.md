## 0. 환경 구축

### 0-1. 지금 이 PC는 이미 끝나 있다 — 확인만 하면 된다

WSL 터미널에서 아래 네 줄을 붙여넣는다. 네 줄이 모두 값을 뱉으면 준비 완료다.

```bash
python3 -V                                            # Python 3.14.4
git -C ~/ardupilot rev-parse --short HEAD             # c2b898a
ls -l ~/ardupilot/build/sitl/bin/arducopter           # 5.8 MB 실행파일
PYTHONPATH=~/ardupilot/modules/mavlink python3 -c "from pymavlink import mavutil; print('OK')"
```

네 번째 줄이 중요하다. **pymavlink는 이 PC에 설치되어 있지 않다.** `pip install pymavlink`는
`Python.h`가 없어 실패하고 sudo도 없어 설치할 수 없다. 대신 ArduPilot이 서브모듈로 가지고 있는
원본을 그대로 쓴다. 그래서 모든 실험 스크립트는 첫머리에서 이 경로를 직접 넣는다.

```python
sys.path.insert(0, "/home/shine/ardupilot/modules/mavlink")
```

설치 대신 경로를 쓰는 것이므로 버전이 ArduPilot 커밋에 고정된다. 재현성 측면에서는 오히려 유리하다.

### 0-4. 실행 전 알아둘 세 가지

**시뮬레이션 시각으로 잰다.** 모든 시각은 `time_boot_ms` 기준이므로 배속을 올려도 측정값이
바뀌지 않는다. 이륙은 배속 5로 빠르게, 교란 주입 직후에는 배속 1로 낮춘다.

**`pkill -f arducopter` 를 절대 쓰지 않는다.** 명령줄 문자열이 자기 자신과 겹쳐 실행 중인
셸까지 죽는다(종료코드 144). 반드시 `pkill -x arducopter` 를 쓴다.

**한 비행에 명령 하나만 넣는다.** 주입이 측정 대상인 창 자체를 바꾸기 때문에, 한 비행에
여러 명령을 넣으면 두 번째부터는 의미가 없다. 이것은 실수가 아니라 논문의 관측 결과다(4.1).

대조군 47.5초가 **18.7초로 줄었다.** 접지 속도는 0.49 → 2.50 m/s.

```
Mode change to Loiter failed: requires position
      DO_SET_MODE(LOITER) ack=FAILED  LAND -> LAND

```

**거부됐다.** 그리고 창과 접지 속도가 대조군과 똑같다 — 계통에 아무 흔적이 없다.

전부 **위치 추정을 필요로 하는 모드**다. GPS가 죽었으니 성립할 수 없다.

반대로 `STABILIZE`, `ALT_HOLD`, `GUIDED_NOGPS` 는 자세만으로 되므로 수락된다.

**여기서 알게 되는 것**: 항법을 잃은 기체는 공격자에게 만능 제어권을 주지 않는다.
논문의 `posIndependent(c)` 집합이 바로 이 관측으로 채워진 것이다. 문헌에 없어서 직접 쟀다.

거부군 6종이 대조군과 같은 값을 내므로 **이들이 통제군 역할을 한다**(표 1의 47.10~47.50초 범위).

## 실험 4 — 공격자 모델: 서명이 막는가

여기서부터가 "모의침투"라는 말을 쓸 수 있게 해주는 실험이다.

앞의 실험들은 **정상 지상국이 명령을 보낸 것**이다. 진짜 공격이라면
공격자는 별도 링크로 접근하고, 인증 자격이 없어야 한다.

```bash
$PIPE/run_signing.sh
```

두 번 돈다(약 8분). 출력의 마지막 부분만 보면 된다.

```
[=] 조건 OFF | 서명 미적용
    공격자 채널   tcp:5763  (source_system=99, 미서명)
    실제 모드     ALT_HOLD  -> 주입 성립          ← 남의 명령이 먹혔다

[=] 조건 ON | 서명 활성
    실제 모드     LAND 유지 -> 주입 불성립        ← 같은 명령이 안 먹힌다
```

**두 조건의 차이는 서명 정책 하나뿐이다.**

- 공격자는 **다른 포트(5763)** 로 붙는다 — 정상 지상국(5760)과 물리적으로 다른 링크
- 공격자의 `system id`는 99 — 정상 지상국(250)과 다르다
- 공격자는 **서명 키가 없다**

**여기서 알게 되는 것**: MAVLink에 서명을 걸지 않으면 아무나 명령을 넣을 수 있고,
걸면 막힌다. 이건 방어 권고의 근거가 된다.

> **주의**: `COMMAND_ACK`는 두 조건 모두 `ACCEPTED`로 나온다. 다른 채널로 간 응답이
> 섞여 들어오기 때문이다. **판정 근거는 ACK가 아니라 실제 모드 변화**다.
> 논문 4.5에 이 한계를 적어 두었다.

## 실험 6 — 반복 측정 (논문의 주 결과)

앞의 실험 1~3은 조건당 한 번씩이었다. 한 번으로는 우연인지 알 수 없어
대표 조건과 기준선을 다섯 번씩 반복한다. **논문 표 3의 25비행이 이것이다.**

분석 계획은 측정을 시작하기 전에 `실험설계_반복측정_사전등록.md` 로 확정해 두었다.
결과를 보고 기준을 바꾸지 못하게 하기 위해서다.

```bash
# 조건 하나에 비행 하나. SITL을 매번 재시작한다.
python3 $PIPE/repeat.py BASELINE 1
python3 $PIPE/repeat.py ALT_HOLD 1
python3 $PIPE/repeat.py STABILIZE 1
python3 $PIPE/repeat.py DISARM 1
python3 $PIPE/repeat.py LOITER 1
# rep 를 2~5 로 바꿔 반복
```

조건당 5회씩 25번이면 두 시간쯤 걸린다. 라운드 로빈으로 돌리고
라운드 안의 순서는 고정 시드(20260829)로 섞는다.

**주의** — `analyze_repeat.py` 는 사전 등록 범위인 `rep 1~5` 만 받는다.
시험 삼아 돌린 실행은 다른 번호를 주면 분석에 섞이지 않는다.

## 실험 7 — 무재밍 대조군

실험 2에서 `RTL`·`LOITER`·`POSHOLD` 가 거부되는 것을 봤다.
그런데 **재밍 때문에 거부된 것인지** 확인하려면 재밍 없는 조건이 필요하다.

```bash
python3 $PIPE/nojam_test.py
```

`preflight()` 가 `SIM_GPS1_JAM = 0` 으로 두고, 이 스크립트는 그 뒤에
재밍을 켜지 않는다. 나머지 절차는 같다.

기대 출력:

```
DO_SET_MODE(ALT_HOLD) ack=ACCEPTED -> ALT_HOLD
DO_SET_MODE(RTL)      ack=ACCEPTED -> RTL
DO_SET_MODE(LOITER)   ack=ACCEPTED -> LOITER
DO_SET_MODE(POSHOLD)  ack=ACCEPTED -> POSHOLD
```

재밍이 있을 때 막히던 세 종이 전부 통과한다.
**교란이 더하는 것은 새로운 공격 수단이 아니라 회수 수단의 제거**라는 것이
여기서 실험으로 확인된다.

## 실험 8 — 분석 재현 (SITL 없이 30초)

이미 쌓인 실행 기록만으로 논문의 표와 통계값을 다시 만들 수 있다.
SITL 도 비행도 필요 없다.

```bash
cd $PIPE && python3 analyze_repeat.py
```

나오는 값:

| 항목 | 값 |
|---|---|
| 무주입 기준 중앙값 | 48.35초 |
| ALT_HOLD / STABILIZE / DISARM | 18.55 / 5.95 / 0.30초 |
| H1 Mann-Whitney | U = 25.0, p = 0.0079, Holm 보정 0.024 |
| H2 TOST (마진 ±2.0초) | p = 0.25 — **동등성 불성립** |

H2 가 성립하지 않은 것도 그대로 보고한다. 기준선이 8:2 로 갈리는
이봉 분포 때문이며, 원인은 `diag_land.py` 로 따로 진단했다.

## 결과 파일이 어디에 쌓이나

```
pipeline/
  runs/          판정 결과 JSON (실행마다 하나, 고유 ID)
  figs/          demo_visual.py 가 만든 그래프
  scripts/       LLM 생성물에서 변환된 실행 스크립트
  tlogs/         원시 MAVLink 로그 (2026-08-30 이후 실행분만)
  generated.json LLM 생성 원문 + 게이트 결과
  compare_TLP.json  템플릿 대조 결과
  repeat_result.json 반복 측정 분석 출력
```

실행 ID 규칙: `R-*` 반복 측정 · `D-*` 진단 · `M-*`/`MIS-*` 단일 측정 ·
`NJ-*` 무재밍 대조 · `SC-*` 파이프라인 생성물 실행.

각 판정 JSON에는 **코드 해시·ArduPilot 커밋·모델명·실행 시각**이 함께 들어 있다.
나중에 "이 숫자가 어느 코드로 나온 것인가"를 되짚을 수 있게 하기 위해서다.
